## 1. 무엇을 만들려는 것인가

**밤새 녹음된 소리만으로 30초마다 수면 단계를 맞히는 모델.** 최종 제품은 스마트폰 앱이다.

```
           밤새 녹음된 오디오
                  │
        30초씩 자른 epoch (하룻밤 약 500~900개)
                  │
                모델
                  │
     Wake / REM / Light / Deep  (각 epoch 마다 하나)
```

- **Light** = N1 + N2 (얕은 수면), **Deep** = N3 (깊은 수면)
- **입력은 오디오뿐이다.** EEG 같은 생체신호는 쓰지 않는다.
- **PSG(수면다원검사)는 정답 라벨만 제공한다.** 모델 입력이 아니다. 이 구분을 놓치면 이후 내용이 전부 헷갈린다.
- **계약 목표:** Macro-F1 ≥ 0.60, Cohen's κ ≥ 0.50, Accuracy ≥ 0.60

### 왜 Accuracy 를 안 보는가

데이터의 **81%가 Light** 다. 그래서 **"전부 Light"라고 찍기만 해도 Accuracy 0.814** 가 나온다. 같은 예측의 Macro-F1 은 0.224 다.

Macro-F1 은 네 클래스의 F1 을 **동등하게 평균**하므로 소수 클래스를 무시하면 점수가 안 나온다. 그래서 주 지표다.
이 문서의 모든 판단은 Macro-F1 기준이다.

| V3 287명 전체 | N2 | N1 | Wake | N3 | **REM** |
| --- | ---: | ---: | ---: | ---: | ---: |
| 비율 | 73.2% | 9.5% | 7.7% | 4.8% | **4.8%** |

- 녹음 길이 중앙값 **4.45시간** — full night 이 아니다

## 3. 수치를 읽는 법 — 반드시 알아야 할 함정 둘

이 프로젝트에서 "0.53 나왔다"는 말은 그 자체로 의미가 없다. 두 가지 보정이 필요하다.

### 함정 1: best-epoch 선택 부풀림

학습 도중 **validation 이 가장 좋았던 epoch** 을 골라 보고한다. 그 epoch 은 운이 좋았을 수 있다.

측정 방법은 간단하다 — best epoch 점수에서 **바로 앞뒤 epoch 평균**을 뺀다. 이 트랙의 실측:

| 학습 방식 | 부풀림 |
| --- | ---: |
| 동결 embedding 위 학습 | +0.011 ~ +0.016 |
| encoder 재학습 | +0.010 ~ +0.030 |
| end-to-end (예산 부족) | **+0.087** |
| end-to-end (충분 학습) | +0.018 |

**부풀림이 크다는 건 그 결과가 우연한 스파이크라는 신호다.** 실제로 +0.087 짜리 실험(choihy-e011)은 학습 곡선이
ep6 0.400 → ep7 **0.477** → ep8 0.379 였다. 봉우리 하나였다.

### 함정 2: 고정 validation 의 낙관 편향

같은 44명으로 수십 번 비교하면 그 44명에 맞춰지게 된다. 5-fold CV 로 바꾸면 점수가 떨어진다.
**이 트랙에서 실측한 편향은 +0.0397** 이었다(§5-8).

> **따라서 판단은 항상 "같은 seed / 같은 fold 끼리의 차이(paired)"로 한다. 절대값은 참고용이다.**

## 4. 연구 흐름

각 단계는 **질문 → 실험 → 답 → 다음 질문** 으로 이어진다.

### 4-1. 파이프라인이 돌아가는가 (choihy-e001, e002)

가장 단순한 것부터 만들었다.

```
B0 :  30초 log-Mel → CNN → 4-class           →  Macro-F1 0.3631
B1 :  B0 를 얼리고 그 출력 40개(=20분)를 BiLSTM 에 넣어
      가운데 20개를 예측                       →  Macro-F1 0.4340
```

B0 는 성능이 목적이 아니라 **오디오-라벨 정렬, 라벨 매핑, 평가 코드가 맞는지** 확인하는 단계였다.
B1 에서 **+0.071** 이 나오면서 "시간 문맥이 도움이 된다"가 확인됐다. 여기까지는 순조로웠다.

> **참고 — "동결 2단계"라는 설계.** B0 를 학습한 뒤 **얼려서** 그 출력(embedding)을 파일로 저장해 두고, B1 은 그 저장된
> 벡터만 읽어 학습한다. 실험 한 번이 100초로 줄어드는 큰 장점이 있다. **나중에 이게 발목을 잡는다(§4-6).**

### 4-2. 시간 문맥을 더 주면 나아지는가 (e004, e005) — 아니었다

자연스러운 다음 질문이었다. 세 번 시도해서 세 번 실패했다.

| 시도 | 결과 |
| --- | --- |
| 문맥 40 → 80 epoch (20분 → 40분) | −0.002 |
| BiLSTM → Transformer (40 문맥) | −0.027 |
| BiLSTM → Transformer (80 문맥) | −0.023 |

**시간 축은 막혔다.** 나중에 알고 보니 다른 트랙(byoungjun `bj-e037`)도 밤 전체 문맥까지 시험해 같은 결론에 도달했다 —
causal 0.517 = bidirectional 0.517. 문맥은 포화 상태다.

### 4-3. 그럼 병목은 어디인가 (e006) — encoder 였다

시간 모델이 아니라면 **30초 안의 소리를 표현하는 부분**이 문제일 것이다. CNN 을 Conformer 로 바꿨다.

```
0.4340 (CNN encoder)  →  0.4833 (Conformer encoder)      +0.049
```

단일 실험 최대 상승폭이었다. **"병목은 음향 표현이다"** 가 확립됐고 이후 방향이 여기로 잡혔다.

### 4-4. 잠깐 — 데이터가 이상하다 (e007)

성능을 올리던 중 Light 81% 가 계속 걸렸다. 원본까지 파고들어 §2 의 결과를 얻었다.
**REM 이 없는 피험자가 35.5%.** 이 시점에서 목표 0.60 이 구조적으로 어렵다는 게 확정됐다.

이건 나쁜 소식이지만 **가장 가치 있는 발견**이었다. 이후 모든 결과를 해석하는 틀이 됐다.

### 4-5. 다른 트랙의 기법을 가져오기 (e008, e009, e010)

팀의 다른 연구자(byoungjun)가 확보한 기법들을 내 파이프라인에 하나씩 이식하며 단일 변수로 검증했다.

**먼저 값싼 것들부터** (동결 embedding 위, 런당 2분):

| 이식한 것 | 결과 |
| --- | --- |
| 시각 특징 (밤의 몇 시인지) | **−0.009** — 3 seed 전부 음수 |
| cosine 학습률 스케줄 | +0.002 (무효) |
| label smoothing | −0.003 |
| REM 가중치 ×2 | −0.003 |

전부 기각. 특히 시각 특징이 해로웠던 게 흥미롭다 — 이 기법이 담고 있는 사전지식은 "Deep 은 전반부, REM 은 후반부"인데,
**중증 무호흡 + split-night 코호트에는 그 구조가 없다.** 데이터 제약이 여기서도 드러났다.

**다음은 encoder 를 다시 학습해야 하는 것들** (런당 70분):

| 이식한 것 | 원시 | 부풀림 보정 | 판정 |
| --- | ---: | ---: | --- |
| 대조군 (아무것도 안 함) | 0.4716 | 0.4692 | 기준 |
| night_norm (피험자별 음량 정규화) | 0.4952 | 0.4652 | **기각** — 부풀림이 이득을 다 먹음 |
| **SpecAugment** (스펙트로그램 일부 가리기) | **0.5052** | **0.4939** | **채택** |
| 둘 다 | 0.4912 | 0.4808 | **기각** — REM 이 0.197 → 0.147 로 붕괴 |

> **여기서 대조군을 따로 돌린 이유가 있다.** 이전 최고 기록은 GPU 3 에서 학습됐는데 이번엔 GPU 2 를 썼다.
> 확인해 보니 **GPU 가 다르면 결과가 비트 단위로 재현되지 않는다** (§6-2). 대조군 없이 비교했다면 GPU 효과를
> 성능 향상으로 착각했을 것이다.

**마지막으로 지식 증류(KD)** — PSG 생체신호를 보는 강한 teacher(Macro-F1 0.672)의 출력을 흉내내게 하는 기법:

```
0.4952 (SpecAugment 만)  →  0.5071 (+ cosine + gated KD)      +0.012, 3 seed 전부 양수
```

채택. 여기까지가 **동결 2단계 구조의 최대치**였다.

### 4-6. 동결을 풀다 (e011, e012) — 가장 큰 구조적 개선

§4-1 의 "동결 2단계"를 다시 보자. encoder 를 얼려 버리면 encoder 는 **"고립된 30초를 분류하는 데 유용한 특징"만**
배우고 멈춘다. 문맥 속에서만 의미가 생기는 특징은 배울 수 없다.

그래서 encoder 와 시간 모델을 **함께** 학습하도록 바꿨다.

**1차 시도(e011)는 0.4765 로 실패처럼 보였다.** 하지만 폐기하지 않았다 — 부풀림이 **+0.087** 로 비정상이었고
50 epoch 예산 중 16 에서 멈췄다. **미학습이지 무효가 아니었다.**

예산(50 epoch)과 정규화(SpecAugment, cosine)를 붙여 다시 돌렸다:

```
0.5071 (동결 2단계 최고)  →  0.5310 (end-to-end)      +0.024
Deep F1  0.265  →  0.399
```

3 seed 재현(e014)에서 **0.5351 ± 0.0040** 으로 확정됐다. 표준편차가 매우 작아 믿을 만한 수준이었다.

> **정직하게 짚을 것:** 이건 팀 차원의 새 발견이 아니다. byoungjun 파이프라인은 **처음부터 end-to-end** 였다.
> 이 트랙만 스스로 동결 설계를 택했다가 뒤늦게 따라잡은 것이다.

### 4-7. 마무리 시도들 (e013, e015, e016, e017) — 전부 실패

parent 확정 후 성능을 더 밀어보려 네 번 시도했고 **네 번 다 못 넘었다.**

| 시도 | 결과 | 배운 것 |
| --- | ---: | --- |
| end-to-end + KD (α 0.3) | +0.004, 1/3 양수, **분산 6배** | KD 가 공동 학습을 불안정하게 만든다 |
| encoder 용량 2 → 4 blocks (+65% 파라미터) | +0.006, 기준 미달 | **용량은 병목이 아니다** |
| KD 용량 절반 (α 0.15) | **−0.009, 0/3 양수** | 용량 문제가 아니다 → KD 라인 종료 |
| 3-seed 확률 앙상블 | +0.001 | κ +0.018, Acc +0.013 인데 **REM 이 −0.042** |

**하나의 패턴이 반복된다.** 거의 모든 레버가 Wake·Light·Deep·κ·Accuracy 는 올리는데 **REM 만 안 움직인다.**
앙상블이 가장 선명하다 — κ 는 확실히 올랐는데 REM 이 무너져 Macro-F1 이 제자리다.
**Macro-F1 은 REM 에 발목이 잡혀 있고, REM 은 §2 의 데이터 문제다.**

KD 실패의 가설: **teacher 의 출력은 깨끗한 오디오로 만들었는데, end-to-end student 는 SpecAugment 로 손상된 입력을 본다.**
동결 경로(e010)에서는 KD 가 깨끗한 캐시에 적용돼 이 불일치가 없었고, 거기서는 +0.012 가 나왔다.

### 4-8. 5-fold CV 검증 (e018) — 반전

성능 축이 모두 막힌 시점에서, 남은 가장 가치 있는 일은 **숫자를 팀이 비교할 수 있는 형태로 만드는 것**이었다.

0.5351 은 **팀에서 가장 낙관적인 프로토콜**(고정 44명 + best epoch)에서 나온 값이다. 다른 연구자들은
10 seed 또는 5-fold CV 로 보고한다. 같은 자리에 놓을 수 없는 숫자다.

팀 공용 5-fold CV manifest 로 같은 설정을 다시 돌렸다.

| fold | 0 | 1 | 2 | 3 | 4 | **평균** |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Macro-F1 | 0.4694 | 0.4810 | 0.4988 | 0.5264 | 0.5013 | **0.4954 ± 0.0217** |

**결과가 이야기를 바꾼다.**

| | 값 |
| --- | ---: |
| 고정 val-44 (3 seed) | 0.5351 ± 0.0040 |
| **5-fold CV** | **0.4954 ± 0.0217** |
| **낙관 편향** | **+0.0397** |
| fold 간 sd / seed 간 sd | 0.0217 / 0.0040 = **5.4배** |
| byoungjun CV 기준선 대비 | 0.498 ± 0.019 → **−0.0026** |

> **결론: 팀 공통 기준에서 이 트랙의 Conformer end-to-end 모델은 기존 CNN 파이프라인과 동등하다.
> 앞서 보였던 우위는 모델 품질이 아니라 측정 프로토콜이었다.**

실망스럽지만 **이것이 이 실험의 목적이었다.** 검증하지 않았다면 잘못된 우위를 근거로 통합을 제안했을 것이다.

## 6. 방법론에서 배운 것 (팀 전체에 해당)

### 6-1. 선택 부풀림은 상수가 아니다

팀은 +0.049 라는 실측치를 쓰고 있지만, 이 트랙에서 재보니 학습 방식마다 **+0.011 ~ +0.087** 로 달랐다.
**부풀림 크기 자체를 결과 신뢰도 지표로 쓸 수 있다** — 크면 그 점수는 봉우리 하나다.

### 6-2. GPU 가 다르면 비트 단위 재현이 안 된다

| 조건 | 결과 |
| --- | --- |
| 같은 GPU 에서 두 번 실행 | 해시 **완전 일치** |
| 다른 GPU | 요소의 약 0.05% 가 float16 2 ULP 이내로 다름 |

차이는 미세하지만 **그게 downstream 학습을 발산시켜 같은 encoder 인데 최종 점수가 0.0117 달랐다.**
→ **기존 보고서들이 적어둔 checkpoint 해시는 GPU 종속이며, 다른 GPU 에서의 재현 검증 기준으로 쓸 수 없다.**

### 6-3. 단일 seed 값은 대표값이 아니다

SpecAugment 실험의 첫 보고값 0.5052 는 3 seed 중 운 좋은 하나였고 평균은 0.4952 였다.

### 6-4. encoder 단독 성능으로 최종 성능을 예측할 수 없다

`night_norm + SpecAugment` 조합은 **encoder 단독 성능이 가장 좋았는데(0.4458)** 최종 성능은 SpecAugment 단독보다 낮았다.
B0 학습률 실험에서도 같은 패턴이었다. **중간 단계 지표를 믿지 말 것.**

### 6-5. 조합이 항상 낫지는 않다

byoungjun 트랙에서는 네 기법이 "단독 무효, 결합해야 +0.054" 였는데, 이 트랙에서는 **결합이 단독보다 나빴다**
(REM 붕괴). encoder 가 다르면 조합의 필요성도 다르다.

## 7. 다음에 할 일

1. **byoungjun 에게 KD 결과 공유 (긴급).** 그쪽 현재 최고 설정이 `증강 + KD` 인데 **단일 seed** 다.
   이 트랙의 6개 런은 증강과 KD 를 함께 쓰면 공동 학습에서 불안정하고 **용량을 줄여도 나아지지 않음**을 보인다. 시간 낭비를 막을 수 있다.
2. **3-stage 주 지표 재협의에 증거 제공.** 모든 레버가 REM 만 못 움직이고, 287명 중 102명이 REM 0 이다.
   byoungjun 이 이미 열어둔 논의(`bj-e033`)에 독립 증거를 보탠다.
3. **Conformer encoder 를 모듈로 제안할지 결정.** CV 에서 동등하므로 "더 낫다"고 주장할 수 없다.
   다만 다른 encoder 계열이라 앙상블 다양성 측면의 가치는 별개로 검토할 수 있다.

**하지 말 것:** encoder 변형 추가, KD 재시도, 단일 seed 이상치 추격(한 번 0.5652 가 나온 적 있으나 같은 설정 평균은 0.5394, 3 seed 중 1개만 양수였다).
